Memo read access is decided in two places that encode the same rules. Fetching one memo uses a Go function in core/access. Listing memos uses a SQL condition built by each database driver and applied inside the query. I didn't modify any files.

The visibility rules

core/access/memo.go
- CheckMemoReadContext(ctx MemoReadContext) MemoReadDecision (line 92) is the rule for a single memo. It checks these in order:
  a. The memo is hidden (not found) if it's missing, its creator is invalid, its visibility value is unknown, or it's a SPACE memo with no space or a deleted space.
  b. The memo must be
  c. An instance admin can read any memo that passes steps 1–2.
  d. An ARCHIVED memo is readable only by its author.
  e. A share token opens the exact shared memo, but never a SPACE memo.
  f. Then the visibility level decides:

| Visibility                  | Who can read it                                                                                 |
|-----------------------------|-------------------------------------------------------------------------------------------------|                 | PUBLIC              if the instance allowsanonymous access; otherwise any active signed-in user |                | PROTECTED           n user                                                     |
| PRIVATE                     | The active author only                                        |
| SPACE (store.SpaceAudience) | Active users who are active members of the memo's space. The author gets no automatic access.   |                 
- Helpers: IsActiveUser, IsInstanceAdmin, MemoReadDecision.Allowed. The types involved are MemoReadContext, MemoReadDecision, MemoReadDenial   MemoReadClass.

core/access/memo_resolve.go gathers the inputs for that check from the store:
- ResolveMemoReadFacts: works out whether the creator is valid and whether the space exists. These don't depend on who is reading.
- MemoReadFacts.WithViewer is an active spacemember. It skips the lookup for inactive users and admins.
- ResolveMemoReadContext: runs the two steps above together.

store/memo.go
- The MemoAccessScope struct (line 175) is the access filter. It's carried on FindMemo.Access (line 84).

Each driver's memo_access.go builds the SQL condition (you get a WHERE clause, not a Go decision):
- store/db/sqlite/memo_access.go → sqliteMemoAccessPredicate
- store/db/mysql/memo_access.go → mysqlMemoAccessPredicate
- store/db/postgres/memo_access.go → postgresMemoAccessPredicate

Taking SQLite as the example, the condition allows:
- PUBLIC rows if AllowPublic is set;
- for an active user: PRIVATE rows they created, PROTECTED rows, and SPACE rows where they are an ACTIVE space_member with role ADMIN or USER.

It also enforces the s function: knownvisibility value, valid creator, existing space for SPACE memos, and archived rows visible only to their creator. If no case applies, it returns
1 = 0 so nothing match

The condition is added to the query in store/db/sqlite/memo.go:177,
store/db/mysql/memo.gomo.go:172. It's appliedbefore LIMIT/OFFSET, so hidden rows can't change counts or pagination.
